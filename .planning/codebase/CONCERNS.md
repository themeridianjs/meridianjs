## Critical Issues

### Race Conditions
- **Issue number generation**: `Issue.number` and similar sequential IDs are vulnerable to concurrent request collisions — no DB-level locking or sequence.
- **Task list position updates**: Position reordering operations are not atomic; concurrent reorders can corrupt ordering.

---

## High Priority

### Test Coverage Gaps
- Only 3 test files exist for the entire framework (`packages/framework`, `packages/framework-utils`, auth middleware).
- Critical business logic (workflow engine, event bus, module loader) has no automated tests.
- No integration tests for the full request lifecycle (route → workflow → event → subscriber).

### Scaling Limits
- `@meridianjs/event-bus-local` uses Node.js `EventEmitter` — not distributed, does not survive process restart, not suitable for multi-instance deployments.
- Per-module `MikroORM` instances create separate DB connection pools — no shared pooling, connection count scales linearly with module count.

---

## Medium Priority

### Error Handling Issues
- Silent event bus fallback: if Redis is unavailable, errors may be swallowed rather than surfaced.
- Workflow compensation errors are caught but not consistently re-thrown or logged.
- Subscriber errors in event handlers can fail silently without alerting the caller.

### Performance Bottlenecks
- N+1 query pattern in time log / activity reporting — related records fetched in loops.
- Large React components (KanbanBoard, ProjectIssuesPage) trigger full re-renders on minor state changes.
- No query result caching at the API layer.

### Missing Infrastructure
- No explicit database migration system — dev mode uses `updateSchema({ safe: true })` (additive only, never drops). Production schema changes require manual SQL.
- No distributed transaction support across modules — cross-module workflows rely on saga compensation only.
- No audit log export functionality despite `@meridianjs/activity` recording events.

---

## Low-Medium Priority

### Security Issues
- Email comparison is case-sensitive in auth module — `user@example.com` and `User@Example.com` treated as different accounts.
- Password reset tokens have no expiry enforcement at the DB level (only checked in application logic).
- JWT `jti` (JWT ID) for token revocation is not persisted — revoked tokens remain valid until expiry if server restarts.
- Rate limiting applies only to `/auth` and `/admin` prefixes — other routes unprotected.

### Fragile Areas
- **Partial module loader initialization**: if a module loader throws mid-registration, the container may be in a partially-initialized state with no rollback.
- **Plugin route conflicts**: two plugins exporting the same route path will silently overwrite each other — no conflict detection.
- **Private container field pattern**: `MeridianService` uses `#container` private field; subclasses must store their own reference (documented but easy to miss).
- **Project transfer workflow**: transfers across workspaces rely on multiple sequential service calls — no transaction boundary.
